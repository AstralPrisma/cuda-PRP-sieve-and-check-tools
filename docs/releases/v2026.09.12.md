# v2026.09.12 — GHCWSV 1.2, adaptive work batches

GHCWSV borrows GNCWSV's compact-workset rebuild trigger. Its candidate list
was already compacted, but version1.1 sized GPU batches only at startup. As
the list shrank, the same tiny prime batch left less parallel work and kept
paying synchronization/transfer costs. Saving and restarting recalculated the
batch size, which could produce a large real throughput jump.

Version 1.2 recalculates GPU batches after the number of distinct n values
decreases by at least 20% relative to the last scheduling baseline. Prime
generation uses independent larger batches, consumed with a cursor: the
unprocessed tail remains intact. Each chunk commits its safe prime boundary
only after all CUDA work and CPU factor validation complete.

## Usage and compatibility

Existing commands and checksummed v1/v2 candidate files remain compatible.
Adaptive scheduling is on by default; no resieving or conversion is required.

```sh
GHCWSV -b 7 -n 100001 -N 500000 --sign both -P 5e10 -o hc7_both.txt
GHCWSV -i hc7_both.txt -P 5e10 -o hc7_both.txt
```

Use `--work-batching fixed` for the former scheduling strategy as a diagnostic
reference. `workset-rebuild` reports the current distinct-n count and GPU
batch size. `primes_per_s` retains its cumulative-average meaning;
`recent_primes_per_s`, `p_per_s` and `rate_window_s` distinguish recent prime
throughput from movement of the numeric p boundary. ETA uses a recent window
and remains an estimate. This is not GFNSV's candidate-independent root sieve.

## Evidence and limits

- Same b=7, n=100001..500000, both signs, p<=2,000,000: warm original runs
  took 11.365/11.621 seconds wall time; adaptive runs took 2.592/2.522 seconds.
  About 4.5x faster in this bounded fresh-range test, with byte-identical output.
- An already sparse saved range showed no clear improvement (about 1.6–1.8s).
- Original/fixed/adaptive results, independent modular oracles, both signs,
  a 2,100,001-distinct-n multi-launch workset, high-p arithmetic, corrupt states
  and real SIGINT/CTRL_BREAK continuation were checked.
- Windows and Linux packages each contain sm_86, sm_89, sm_100 and sm_120.
  Only sm_89 was GPU-tested, under Windows and WSL on the same RTX4060 Laptop.
  Other targets were cross-compiled and CPU-reference-tested, not GPU-tested.
- Linux artifacts are built for Ubuntu22.04 compatibility, with maximum
  GLIBC_2.34 and static CUDA/C++/GCC runtimes. The NVIDIA driver is still needed.

See [validation](../../GHCWSV/VALIDATION_1.2.md) for detail. Sieve survivors
are not primality results; independently verify important PRP hits.
