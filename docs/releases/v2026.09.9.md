# CUDA PRP: sieve and check tools — v2026.09.9

This suite release promotes **GFPPS's parallel NTT and exact fused-carry
optimization**, retaining its component version **1.0** and checkpoint format.
Other components are unchanged.

| Component | Version |
| --- | ---: |
| GFPS | 4.4 |
| GPRPS | 2.3 |
| GFPPS | 1.0 |
| GFNSV | 1.1 |
| GPRSV | 2.1 |
| GNCWSV | 1.0 |

## GFPPS changes

- Parallel work for the two NTT prime planes, including global and shared
  transform kernels; 1024-point shared tiles with 128 threads.
- Exact fusion of three carry-relaxation passes and carry-map generation,
  while retaining the full CUB scan and arithmetic error conditions.
- Default `--force-ntt-blocks` cap rises from 96 to 256. The option, accepted
  input bounds, result meanings, and opt-in checkpoint interface are unchanged.
- Existing `GFPPS001` checkpoints remain compatible. Stop the executable before
  replacing it and retain the original expression/witness on resume.

No truncated carry shortcut or unbounded carry-backtracking experiment is
included. Fermat PRP testing still does not generate a primality proof.

## Measured gains and validation limits

For the complete 100,001-digit `2*25206!+1` check, same-platform interleaved
before/after exponentiation-time medians were:

| Hardware / OS | Previous path | Optimized path | Throughput gain |
| --- | ---: | ---: | ---: |
| RTX 5090 / Linux | 31.326306 s | 19.082555 s | +64.2% |
| RTX 4060 Laptop / Windows | 42.770754 s | 35.198393 s | +21.5% |

All complete benchmark checkpoints matched byte-for-byte. The million-digit
4060 test measured only a 4096-bit prefix (+6.9% throughput); it did not run
the complete exponent chain. These are finite measurements, not general speed
guarantees or cross-platform benchmarks.

Those timings are from the preceding isolated builds of the arithmetic path
now enabled by default in this release, not fresh full timing runs of every
final artifact.

Optimization validation on both tested platforms includes 60 independent
integer checks, six large-layout prefix comparisons, two complete known
primorial PRPs, old/new checkpoint continuation, and damaged/wrong-parameter
rejection. Linux additionally exercised real SIGINT save/resume. Matching GPU
evidence is specific to **Windows `sm_89`** and **Linux `sm_120`** for those
studies; other builds are not assumed tested. Final artifact evidence is
recorded separately in `BUILDINFO.txt` and the manifest.

The exact final **Windows `sm_89`, Linux `sm_89`, and Linux `sm_120`** binaries
each passed six independent Python/Boost integer smoke cases, cross-Graph
checkpoint continuation with complete-state equality, and a 512-bit large-NTT
prefix. All three prefix checkpoint SHA-256 hashes match. Native cubin and
PTX targets were inspected for all eight builds; other OS/SM combinations
were cross-built only. The final smoke runs did not repeat the full 60-case
suite or complete timing comparisons.

See [the full optimization validation record](../../GFPPS/VALIDATION_optimized_20260909.md)
for methods, arithmetic invariants, and the distinction from historical 1.0
tests. GFPS's separate experimental 5090 optimization is **not** promoted.

## Assets and compatibility

Only GFPPS's eight Windows/Linux architecture binaries are rebuilt. The other
40 executables are reused byte-for-byte from v2026.09.8 after checking current
source/header hashes and old artifact hashes. Their original build/runtime
provenance is retained in `reused_from`; refreshed archives do not imply new
builds or repeated full validation of those five components.

Linux GFPPS is built for Ubuntu 22.04 compatibility, using static C++/GCC/CUDA
runtimes. glibc and the compatible NVIDIA driver remain required; this is
**not a fully static glibc build**. Check the package's `BUILDINFO.txt` for its
measured symbol/dependency floor. This packaging change applies only to
GFPPS, not the other reused Linux tools.
The actual Linux GFPPS dependency inspection found a maximum required GLIBC
symbol version of **2.34**, no dynamic GLIBCXX/libstdc++ requirement, and ELF
dependencies on libm, libc, and the loader.

The release includes twelve component/platform archives, one source archive,
`manifest.json`, and `SHA256SUMS` (15 assets). Check SHA-256 after download and
select the binary matching the GPU's SM target. `sm_86` and `sm_100` builds
have no matching-hardware runtime evidence for this optimization.

Separate PRPNet client ZIPs omit sieves; sieve programs and sources remain in
the full GitHub release. Site download URLs are managed separately from this
repository release.
