# CUDA PRP and sieve tools v2026.09.3

This maintenance release fixes Windows console behavior in the two CUDA PRP
checkers and their matching toolkit clients.

## Changes

- GFPS now handles `SIGINT`/`CTRL_BREAK` at a completed arithmetic boundary,
  writes the latest safe main checkpoint, and exits with status 130.
- GFPS and GSRPS explicitly flush redirected output, so Windows clients show
  progress and checkpoint lines while a check is running.
- The matching Python clients isolate child process groups/sessions, forward a
  single interrupt down the process tree, drain final output, and protect
  cleanup from repeated interrupts.
- Interrupted tasks remain local and resumable; they are not submitted or
  released as completed.

## Build and validation

- Built with CUDA 13.3 for native `sm_86`, `sm_89`, `sm_100`, and `sm_120`.
- Linux and Windows `sm_89` GFPS/GSRPS self-tests passed on an RTX 4060.
- Every emitted binary was inspected to confirm that its cubin target matches
  its filename. Other architecture variants are cross-compiled.
- Windows and WSL interrupt tests confirmed exit status 130, safe checkpoint
  advancement, live output on Windows, no traceback on repeated POSIX signals,
  and no orphan checker process.

PRP results remain probable-prime results and require independent validation.
