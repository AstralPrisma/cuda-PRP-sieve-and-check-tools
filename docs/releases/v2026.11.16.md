# v2026.11.16 — GPRSV_N 1.1 and GPRSV → GPRSV_K rename

This release adds GPRSV_N and renames GPRSV to GPRSV_K. No other component is
rebuilt or changed.

## GPRSV_N 1.1 (new)

GPRSV_N sieves `k*b^n-1` and `k*b^n+1` for a fixed `k` over an exponent interval
`[N1, N2]`. At each prime the problem is a discrete logarithm
`b^n = ±k^-1 (mod p)`; GPRSV_N solves it with a baby-step/giant-step search
(about `2*sqrt(interval)` modular multiplications per prime) instead of a direct
walk. A `--backend walk` path is retained for very short intervals and for
cross-checking the BSGS kernel. Only `k*b^n±1` is supported; `n!`/`n#` forms stay
in GPRSV_K.

- 1.1 defaults to the independent sign mode (`+1`/`-1` separate). The paired/twin
  sieve must be requested with `--paired`, and refuses configurations where
  `p=3` would remove every exponent because 3 divides neither `k` nor the base.
- Output carries `sieved_to`, `nmin`, `nmax` and `terms` in an ABC header, so
  `-i` resumes from the file rather than from its name. `-E` writes full
  `k*b^n±1` expressions for LLR/PFGW/PRST.
- Verified against an independent Python reference (11 parameter sets), against
  the walk/BSGS/host-only paths byte for byte, and against srsieve2 1.8.8 `-c`
  on a `k=1129`, `n=3500000` slice at `p <= 1e10` (identical survivor sets for
  both signs). See `GPRSV_N/VALIDATION.md`.

Same candidate count and depth, GPRSV_N is 5–27x slower than GPRSV_K depending
on interval length and sieve depth; that gap is the discrete-log-versus-one-
inverse difference, not a regression. Details and measured tables are in
`GPRSV_N/README.md`.

## GPRSV_K 2.3 (renamed from GPRSV)

The directory is now `GPRSV_K/`, the source is `src/GPRSV_K.cu`, and build
outputs are named `GPRSV_K_sm_*`. The program, its options, its 2.3 source
content and its validated behaviour are unchanged; the startup banner still
prints `GPRSV`.

The GPRSV 2.3 packages published in v2026.10.29 are retained byte for byte and
their release assets were renamed from `gprsv-2.3-*` to `gprsv_k-2.3-*`. The
files inside those 2.3 archives keep their original `GPRSV_sm_*` names because
they were built before the rename.

## Binaries

Windows and Linux packages for GPRSV_N 1.1 each contain native `sm_86`, `sm_89`,
`sm_100` and `sm_120` binaries, primesieve 12.x, licenses and build metadata.
Physical GPU validation is limited to `sm_89` (RTX 4060 Laptop, Windows and
WSL); the other targets receive compilation, cubin and startup checks only.
Linux packages are built in an Ubuntu 22.04 environment with static C++/CUDA
runtimes.

Sieve survivors are not primes, and a probable-prime hit is not a primality
proof.
