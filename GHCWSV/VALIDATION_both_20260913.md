# GHCWSV 1.1 双符号验证

日期：2026-09-13。Windows / WSL，RTX4060 Laptop（sm_89）。独立临时文件测试，未修改用户既有筛选状态。

- CPU参考路径：6种底数、正负符号，对照独立 Python 模运算枚举。both 与两次单符号的结果并集一致。
- GPU：Windows/WSL各55次命令检查，覆盖 auto/direct/transform、系数预计算、逆指数互素分组及直接回退。包括接近2^62的筛因子和2^32−1的n边界；系数路径特意覆盖正负两侧实际发现因子的情形。
- 对 `2^3*3^2±1` 保留71和73，防止把候选本身当成因子移除。
- 混合存活位：部分n仅有正号、仅有负号或两者，续筛不恢复已删除的符号。
- 拒绝截断、摘要错误、重复/乱序 `(n,sign)`、非法符号、参数和符号模式不匹配；空双符号状态可正常保存和读取。
- Windows单符号与旧1.0构建的6组完整文件逐字节相同，旧v1格式及摘要兼容。
- Windows分块压力：2,100,001个不同n，跨越单核函数200万对的分块边界；最终正号1,400,001、负号1,050,000，与独立模3闭式结果逐项一致。
- Windows真实CTRL_BREAK与WSL真实SIGINT，仅对隔离测试进程发送；中断后的双符号续筛与未中断结果文件逐字节一致。
- 转换器同时验证v1/v2，导出两种符号或按符号过滤；网络模式TYPE行、S/R文件名和表达式对应。
- 八个原生架构构建分别检查 cubin目标、UTF-8横幅、版本及CPU参考路径。仅sm_89具备GPU运行证据，未将其扩展到其他显卡。

候选文件上限320MiB，最多一千万个不同n、两千万个双符号表达式；转换器流式校验并使用紧凑数组保存状态。大范围仍需足够主机内存。

原始结果摘要位于同目录validation中的 `TEST_*`、`EXTENDED_*` 和 `MATRIX_1.1.json`。以上是回归证据，不构成对所有输入无缺陷的证明；筛后存活并不表示已经通过PRP或素性检验。
